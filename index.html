개괄

온톨로지(ontos 존재 + logos 학문)는 "무엇이 존재하며, 어떻게 분류되고 관련되는가"를 묻는다. 이 사이트는 그 질문이 철학에서 공학, AI로 이동한 2,300년의 계보와, 이를 지식 서비스로 구축하기 위한 이론·아키텍처·학습 루트를 담는다.

  • 철학은 존재 분류의 원리를 세운다 — 범주, 본질, 존재론적 커밋.
  • 엔지니어링은 그 분류를 논리(OWL·DL)로 굳히고 생물의학에서 실증한다.
  • AI에서 방향이 뒤집힌다 — LLM이 온톨로지를 만들고, 온톨로지가 LLM을 구속한다.

구축 관점의 한 줄 결론: 모든 쓰기는 스키마 검증을 통과하게 하고, 모든 읽기는 근거 경로를 반환하라.

이론적 토대

퀘인의 통찰 — "어떤 이론이 존재를 커밋하는가는 그 이론의 변수의 값 범위를 보면 안다" — 는 공학 언어로 완벽히 번역된다. 시스템이 참조·저장·추론하는 개체 타입의 집합이 곧 그 시스템의 온톨로지다.

표현 계층과 7대 기능

스택은 응용 → 생성(LLM) → 추론(DL 추론기·SHACL) → 표현(OWL 2/RDF) → 스토리지(그래프+벡터)로 쌓인다. OWL 2 프로파일 트레이드오프: EL 대규모 분류용, RL 규칙 실행용, QL 쿼리용, full DL은 검증 전용.

  1. 추론 — 계층 도출·일관성 검사·인스턴스 분류
  2. 정렬·매칭 — 이기종 온톨로지 연결
  3. 임베딩 — OWL2Vec*류 reasoner-aware 벡터화
  4. 검증 — OOPS! 설계 결함 스캔 + SHACL 데이터 검증
  5. 진화 — 버전 관리와 하위 호환
  6. 구축 자동화 — LLM 기반 용어·관계·공리 추출
  7. 접합 검색 — 온톨로지로 검색 공간 구조화

LLM × 온톨로지

세 번의 계보 전환: 모델에 지식을 굽고 → LLM이 온톨로지를 만들고 → 온톨로지가 LLM을 구속한다.

1. 지식 주입 (2017–2021)

K-BERT는 삼중항을 문장 트리에 주입하고 지식 과잉의 false-positive를 attention 마스크로 막았다. KEPLER는 MLM과 지식 임베딩 손실을 한 사전학습에 묶었다. QA-GNN은 질의 관련 서브그래프를 GNN으로 추론해 언어모델과 융합했다. 한계 — 갱신에 재학습이 필요하다는 것. 이 한계가 그래프를 외부화하는 GraphRAG로 패러다임을 옮겼다.

2. LLM이 온톨로지를 만든다 (2023–2026)

LLMs4OL(2023)이 온톨로지 학습의 4 과제 — 용어 추출, 타입 분류, 택소노미 발견, 관계 발견 — 를 LLM 과제로 재정식화했다. 2025년에는 생성→정제→채움 3단계 에이전트 구축(제품 KG, 속성 커버리지 97% 보고)과 human-in-the-loop 검증 루프가 실무 표준으로 부상했다. 실무 원칙: LLM은 설계자가 아니라 제안자다. 스키마 커밋은 상위온톨로지 정렬과 사람 검토를 거쳐야 한다 — LLM 생성 온톨로지와 전문가 온톨로지의 실증 비교 연구가 아직 없기 때문이다.

3. 온톨로지가 LLM을 구속한다 (2024–2026)

"KG가 LLM 환각을 줄이는가"(2024 서베이)가 가설을 체계적으로 검토했고, OG-RAG(2025)는 질의를 온톨로지 개체·관계로 해석한 뒤 근거 컨텍스트만 전달했다. Conversational Control(2026)은 온톨로지를 경량 구속 프레임으로 써서 설명 가능한 출력 제약을 실증했다. BIM 규정 검사·CVE 평가로 "규칙 준수형 생성"이 패턴화되고 있다.

상호 강화 루프

루프의 신뢰성은 정규화·검증 단계의 강도에 비례한다. 점선(朱)은 사용자 피드백이 다시 제안으로 들어가는 경로다.

GraphRAG × 온톨로지

벡터 RAG의 다중 홉 실패·검색 표류·근거 부재를 그래프 경로가 보완한다. 온톨로지는 검색에 문법을 부여한다.

온톨로지-grounded 4패턴

패턴동작온톨로지 역할예
스키마 구속 검색질의를 개체·관계로 해석 후 경로 수집질의 해석의 문법OG-RAG, FAIR GraphRAG
지식 강화벡터 결과를 KG로 확장확장의 지도KERAG
에이전트형 탐색에이전트가 그래프를 도구로 근거 수집탐색 규칙GRAIL
하이브리드 퓨전그래프 점수+벡터+텍스트 융합채널 정합성 검증기graph-vector fusion

온톨로지 없는 GraphRAG는 스키마리스 그래프 검색으로 퇴화한다. 평가 축 — 다중 홉 정확도, 근거 충실도(faithfulness), 인용 정확성, 공격·노이즈 하의 견실성.

지식 엔진

스토리지·쿼리 계층. 벡터-그래프 하이브리드가 표준으로 수렴 중이다.

  • 통합 엔진: AkasicDB(2026) — vector-graph-relational 일체. TigerVector(2025) — 그래프 DB 안의 벡터 검색.
  • 공동 최적화: RAG-Stack(2025) — 검색 품질과 스토리지 성능을 한 시스템으로 설계.
  • 쿼리: Cypher 계열, LLM 기반 쿼리 생성(Auto-Cypher).
  • 보안: retrieval pivot 공격 — 그래프 경로가 공격 표면이 된다. 경로 신뢰도·provenance 강제 필요.

추론기 배치

full DL 추론(HermiT류)은 온라인에 너무 비싸다. 실무 배치: 스키마 검증·분류는 오프라인 배치, 온라인은 materialization(미리 계산된 추론 그래프) + SHACL 경량 검증, 규칙은 그래프 엔진으로 푸시다운.

구축 로드맵

택소노미에서 진화 루프까지 5단계. 각 단계의 완료 기준이 게이트다.

단계범위완료 기준
1. 택소노미핵심 클래스 50~200개, 상위온톨로지 정렬OOPS 스캔 통과, 전문가 리뷰
2. KG 구축LLM 추출 + 검증 게이트, 인스턴스 적재추출 정밀도 측정, SHACL 통과율
3. 엔진 결합그래프+벡터 하이브리드, 배치 추론다중 홉 hit@k 목표
4. GraphRAG개체링킹→경로확장→퓨전 파이프라인faithfulness 벤치마크 통과
5. 진화 루프피드백 재투입, 스키마 버전 관리무중단 온톨로지 진화

평가 지표 5축

  • 온톨로지 품질 — 함정 수(OOPS), DL 일관성 위반, 정렬률, 공리 밀도
  • KG 품질 — 추출 정밀도/재현율, 개체 해석 정확도, 최신성
  • 검색 — hit@k, MRR, 다중 홉 정확도
  • 생성 — 충실도, 인용 정확성, 환각률
  • 운영 — 스키마 하위호환율, 게이트 통과율, p95 응답

리스크 5건

  1. 스키마 경직성 — 상위온톨로지는 얇게, 제약은 SHACL로 분리
  2. LLM 온톨로지 품질 갭 — 사람 게이트 필수, 표본 감사 지속
  3. 추론 비용 폭발 — EL/RL 온라인, DL 배치 분리
  4. 그래프 공격 표면 — 경로 신뢰도, provenance 강제
  5. 하이브리드 복잡도 — 단일 엔진 우선, 퓨전 계층 정합성 테스트
